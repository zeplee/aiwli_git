# v1.5.18：用 App 自己的「推送提交」实测 + 错误分类器第三次误判

**日期**：2026-10-07
**触发**：用户要求"试一下我这个软件的推送到远程功能"（指 App 内的按钮，不是命令行）

## 一、实测结论（一句话）

**App 的推送链路本身是好的**：按钮→引擎→libgit2 全部正常发起，**证书层已通过**
（`[tls] bundle=…` 有值、`跳过校验=false`，错误是 `class=Os (2)` 而非 `class=Ssl (16)`），
失败**完全在网络路径**：该 App 的流量被用户 VPN 的**按应用分流**送进了隧道，而这条隧道
到 GitHub 被 RST；**没走隧道的直连反而是通的**。

## 二、证据链（全部真机实测）

### 2.1 App 侧：推送确实发出去了，且信任锚已就位

`/data/data/com.aiwli.git/files/gitdeck_error.log`（需 `su -mm`，见 §4 坑）：


- `[tls] bundle=` **有值** ⇒ 1.5.17 的内存注入修复**真的生效了**（上一轮它是 `(未应用)`）

- 两次点击 ⇒ 日志两条（说明第一次"点了没反应"只是横幅 4 秒就消失，动作本身是成功的）

### 2.2 网络侧：按 uid 分流的 VPN，隧道那条路是坏的

`ip rule show`（root）里大量：

```
13000: from all fwmark 0x0/0x20000 iif lo uidrange 10661-10661 lookup tun0
```

| 路径 | uid | 在 tun0 分流表 | 实测结果 |
|---|---|---|---|
| NP 管理器 | 10224 | ❌ 不在 | **直连** `github.com` 200；`<repo>.git/info/refs?service=git-upload-pack` **401**（端点可达、需认证） |
| 容器宿主 App | 10481 | ✅ 在 | 容器内 `git ls-remote` → `Recv failure: Connection reset by peer` |

（容器内 gitee 200 / codeup 302），只对 GitHub 被重置。

**结论：要让 App 推送成功，必须让它的流量不经过这条隧道** ——
把 com.aiwli.git 移出 VPN 的分流应用列表（走直连），或换一个能过 GitHub 的节点。

## 三、错误分类器第三次误判（本轮由实测暴露）

1.5.17 把证书判定提到网络之前，但证书关键字里放了**裸 `'ssl'`**：

```dart
if (has(['ssl', 'certificate', '证书']))   // ← 裸 'ssl'
```

而 libgit2 把**传输层**失败也包成 `SSL error: syscall failure: Connection reset by peer;
class=Os (2)` —— **`SSL error:` 前缀让网络故障命中证书分支**，于是真机横幅显示：

> ~~HTTPS 证书校验失败：远程证书不被本机信任…（自签或内网 CA…）~~
> （原始：push 失败: SSL error: syscall failure: Connection reset by peer; class=Os (2)）

给的处置（导 CA / 关校验）**全都不对症**，又一次把真因带偏。

### 三次误判，同一个错误做法

| 版本 | 错误做法 | 后果 |
|---|---|---|
| ≤1.5.16 | 网络分支对**裸 `'网络'`** 做子串匹配 | 证书错误 → 报成"网络连接失败"（docs/14） |
| 1.5.17 | 证书分支对**裸 `'ssl'`** 做子串匹配 | 网络错误 → 报成"证书校验失败"（本文） |
| 1.5.17 | 网络关键字只有 `resolve host`，漏了 DNS 真实串 | DNS 失败 → 落进泛化的"推送失败"（**回归测试抓到的**） |

⇒ 根因是同一个：**对过短的裸子串做匹配**，且**只测了当时遇到的那一条错误串**。

### 修复

- 证书分支：`['ssl', …]` → `['class=ssl', 'certificate', '证书']`
  （用 libgit2 的 **class 码**做硬信号，`class=Ssl (16)`）
- 网络分支：补 `'reset by peer'`、`'syscall failure'`、`'resolve address'`、
  `'name or service not known'`、**`'class=net'`**；并在"连接被重置"时给可直接照做的提示
  （移出分流列表 / 换节点）
- 新增 `test/friendly_error_test.dart`：把**真机原始串**钉进回归测试，
  并强制断言"真因不能被分类文案吞掉"（`contains('class=Os')` 等）

真机复测横幅（1.5.18）：

> **网络连接失败**：请检查网络后重试。「连接被重置」通常是链路或代理问题：
> 若开着 VPN/代理分流，把本应用移出分流列表（走直连）或换个节点再试。
> （原始：push 失败: SSL error: syscall failure: Connection reset by peer; class=Os (2)）

测试：`flutter test` → **121 passed**（含新增 10 条分类回归）。

## 四、踩到的坑（供下次省时间）

- **Magisk 会把 DenyList 里应用的 `/data/data/<pkg>` 从默认挂载命名空间隐藏**：`su -c`
  下 `ls /data/data/com.aiwli.git` 报 `No such file or directory`，而进程明明在跑。
  要用 **`su -mm`**（全局挂载命名空间）才看得见。这是"文件不存在"的假故障，
  排障时容易被带偏。
- **`su -c` 的 stdout 写 `/data/local/tmp` 会 Permission denied**（`su -c` 未给该路径写权限），
  于是"用文件暂存 + grep"的批量脚本会静默全部失败、给出**假阴性**
  （本轮一度据此误判"App 不走 VPN"）。判定前先确认中间文件真的写成功了。
- App 的错误横幅只显示 **4 秒**（`showSnack` 的 error duration），
  要抓它得点完立刻读屏；更可靠的是直接读 `gitdeck_error.log`。
- 装机脚本必须先落到 `/data/local/tmp`（FUSE 上的 APK 过不了 system_server 的 SELinux 检查），
  `scripts/install_apk.sh` 已固化该步骤。

## 六、1.5.19：`class=Ssl` 不等于证书问题（第四次误判）+ 结构性修复

推文档补记（`9f4de13`）时，抓到一个**和之前都不同**的错误：

```
[18:48:47] push 失败: SSL error: unknown error; class=Ssl (16)
```

**`class=Ssl` + `unknown error` 不是证书问题** —— 它是 OpenSSL 在 TLS 握手中被掐断的
典型报法（`SSL_ERROR_SYSCALL` 拿不到 errno → "unknown error"）。同一时段还抓到：

```
[18:53:02] push 失败: failed to connect to github.com: Software caused connection abort; class=Os (2)
```

两次都是链路抖动，**重试即成功**（`9f4de13` 后来一次就推上去了）。

### 教训：`class=Ssl` 是"SSL 层"，不是"证书"

libgit2 的 `ErrorClass::Ssl` 覆盖两类完全不同的事：

| 情况 | 真实串 | 正确处置 |
|---|---|---|
| 真证书校验失败 | `the SSL certificate is invalid; class=Ssl (16)` | 导 CA / 换 SSH |
| 握手中被掐断 | `SSL error: unknown error; class=Ssl (16)` | 重试 / 换链路 |

⇒ 所以判定顺序必须是：**先认传输特征**（`syscall failure` / `reset by peer` /
`unexpected eof` / `connection abort` / `ssl error: unknown error`）→ 剩下的
`class=Ssl` 或 cert 字样**才**判证书。

### 顺带做了结构性修复：分类只看**第一行**

前三轮误判其实有一个共同的可乘之机：**引擎会在原始错误后面追加「提示：…」**
（Rust 的 `transport_hint`），而那段文案里含「网络安全」「证书校验失败」等字样。
只要分类器拿**整段**去匹配，就会被自己的提示文案污染。

现在 `friendlyError` 只取 `raw.split('\n').first` 做匹配 ——
**不管提示里写了什么词，都不可能再影响分类**。这比"把关键字列全"可靠：
前者是结构隔离，后者只能靠穷举（已经穷举失败三次）。

### 回归测试

`test/friendly_error_test.dart` 增到 **14 条**，新增的 4 条正对着本次的两个真实串
和"提示污染"：

- 握手被掐断（`class=Ssl` + `unknown error`）→ 判网络，且保留 `class=Ssl`
- `Software caused connection abort` → 判网络
- **网络错误 + 证书提示 → 仍判网络**（断言 `startsWith('网络连接失败')`）
- **证书错误 + 证书提示 → 仍判证书**

> 注意后两条必须用 `startsWith` 断言：展示文案里会附原始错误，而原始错误里
> 就含提示原文（含「证书校验失败」四字）—— 用 `contains` 会自欺。

`flutter analyze` → No issues found；`flutter test` → **125 passed**。
