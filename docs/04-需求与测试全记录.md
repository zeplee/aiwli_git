## 1. 产品需求

### 1.1 背景

在 Android 手机上做 Git 日常操作（查改动、暂存、提交、分支、同步）缺少顺手的工具：
桌面 Git 客户端无法在手机上用，通用终端 + git CLI 触屏体验差。AiwliGit 是一个
**手机原生 Git 工作台**：libgit2（git2 crate）引擎 + Flutter UI，所有数据只存本机。

### 1.2 目标

| # | 目标 | 验收 |
|---|------|------|
| G1 | 打开/克隆/浏览本地 Git 仓库 | 手机存储内任意 git 仓库可打开 |
| G2 | 工作台核心操作 | 状态一览 → 文件 diff → 暂存 → 提交，四步内完成 |
| G3 | 分支/历史/Stash 管理 | 切换、新建、删除、重命名、合并、回退、cherry-pick、revert、stash 全套 |
| G4 | 远程同步 | fetch / pull / push（含 force 二次确认），凭据加密保存 |
| G5 | MCP 接口 | AI 工具（Kelivo 等）通过 MCP 直接调用全部 Git 能力，免手动 |
| G6 | 离线优先 | 除网络同步外全部功能离线可用 |

### 1.3 非目标（明确排除）

- 商业化（授权/付费/防破解）——按需求排除
- 多语言（仅中文）
- iOS / 桌面端首发（Flutter 代码保持跨平台结构，桌面为降级回退）

### 1.4 用户故事（核心）

- 作为开发者，我在地铁上想快速查看仓库有没有未提交的改动并提交 → 工作台状态卡片
- 作为开发者，我想让 AI 助手（Kelivo）直接帮我暂存提交推送 → MCP 服务
- 作为用户，我的 GitHub 令牌不能明文躺在手机上 → Keystore 加密存储
- 作为新用户，我不知道要授权存储权限 → 首次引导 + 权限横幅 + 一键跳系统设置

## 2. 开发文档

### 2.1 技术栈与架构

```
Flutter (Dart 3.13 / Flutter 3.47) ──FFI──▶ rust_lib_gitdeck (libgit2/git2)
     │                                          ▲
     │── dart:io HttpServer ◀── MCP over HTTP ──┘  （同一引擎，同一分发）
     │── MethodChannel (gitdeck/secure, gitdeck/sys) ──▶ MainActivity.kt / McpService.kt
     │       │                                              │
     │       │── AndroidKeyStore AES/GCM（凭据加密）          │── 前台服务保活（dataSync）
     │       └── 存储权限状态 / 跳系统设置
     └── code_cache/gitdeck_prefs.json（偏好 + 密文凭据）
```

- **引擎分发**：`RustLib.call(method, payload)` 统一 JSON 入口（`gitdeck_call` + `gitdeck_free`
  两符号收口），45 个操作；Dart 侧 `Isolate.run` 包裹同步调用不卡 UI。
- **MCP 服务器**：`lib/mcp/server.dart` 纯 Dart `HttpServer`，Streamable HTTP
  （POST /mcp，JSON-RPC 2.0），无状态（不签发 session id），仅监听 `127.0.0.1`，
  可选 Bearer 令牌；`lib/mcp/tools.dart` 定义 32 个工具，1:1 映射引擎分发。
- **凭据加密**：`MainActivity.kt` 内 AndroidKeyStore AES/GCM（密钥不出 Keystore），
  Dart 只存密文 `credEnc`（base64(iv‖ct)）；旧明文条目首次读取自动迁移并删除；
  Keystore 密钥丢失（卸载重装）时密文自动作废。桌面无通道时回退明文（文档化限制）。
- **保活**：MCP 启用即启动 `McpService`（前台 dataSync 服务 + 常驻通知），
  防 MIUI 冻结后台应用导致 MCP 停摆。
- **错误提示**：`friendlyError()` 统一映射引擎错误 → 人话 + 下一步动作。

### 2.2 目录结构

```
lib/
  main.dart            入口
  core/                prefs.dart（偏好+密文凭据）secure_store.dart sys_access.dart
  engine/ffi.dart      FFI 分发 + 45 个类型化 helper
  mcp/                 server.dart（HTTP MCP）tools.dart（32 工具目录）
  pages/               launcher 工作台 历史 分支 stash remotes(设置)
  ui/main_shell.dart   底部导航（工作台/历史/暂存/分支/设置）
  widgets/             dialogs.dart（统一对话框+friendlyError）commit_detail.dart
android/.../kotlin/dev/gitdeck/  MainActivity.kt（2 通道）McpService.kt（前台保活）
rust/src/api/dispatch.rs        引擎分发（rust match 臂）
```

### 2.3 MCP 工具目录（32 个）

| 分类 | 工具 |
|------|------|
| 发现 | `git_recents` `git_open` `git_clone` |
| 工作台 | `git_status` `git_stage` `git_unstage` `git_discard` `git_commit` `git_diff_file` |
| 历史 | `git_log` `git_commit_detail` `git_diff_revs` `git_blame` |
| 分支 | `git_branches` `git_checkout` `git_branch_create` `git_branch_delete` `git_branch_rename` `git_merge` `git_reset` `git_revert` |
| Stash | `git_stash_list` `git_stash_push` `git_stash_apply` `git_stash_pop` `git_stash_drop` |
| 远程 | `git_remotes` `git_fetch` `git_push` `git_pull` `git_conflicts` `git_resolve_conflict` |
| 配置 | `git_config_get` `git_config_set` |

危险操作（`git_discard` `git_reset` `git_push force`）在工具描述中明确标注后果。

### 2.4 MCP 客户端接入

同机（如 Kelivo）：
```json
{ "url": "http://127.0.0.1:8613/mcp", "transport": "http" }
```
设置令牌后加 `"headers": {"Authorization": "Bearer <令牌>"}`（App 内一键复制）。

电脑上的 AI 工具：先 `adb reverse tcp:8613 tcp:8613`，再连同一地址。

## 5. 测试过程中发现并修复的缺陷（本轮闭环）

| # | 缺陷 | 根因 | 修复 |
|---|------|------|------|
| D1 | **启动即崩** `ForegroundServiceDidNotStartInTimeException` | `startForegroundService()` 产生"5s 内必须 startForeground"的系统义务；stopSelf 兜底不能豁免 | 改用普通 `startService`（无该义务），Service 在 onStartCommand 自行 startForeground，失败 stopSelf 不崩 |
| D2 | **MCP 响应体全空**（200 + content-length:0） | `Content-Type: application/json` 未带 charset → Dart HttpServer 按 Latin-1 编码 → **写含中文的响应直接抛** "Contains invalid characters" 被静默吞 | `Content-Type: application/json; charset=utf-8`（一行修复，让 MCP 真机可用） |
| D3 | **MCP 自动启动失效** | `startIfEnabled()` 在 `runApp` 前调用，MethodChannel 未连接，invokeMethod 静默失败；且被防重入跳过 | 调用挪到 `LauncherPage.initState`（engine 完全就绪的安全点） |
| D4 | FGS 类型 `specialUse` 是 API 34 才有 | Android 12 不识别 | 改标准 `dataSync` 类型 |
| D5 |MIUI 冻结后台 app → MCP 停摆（实测 ping 000 + 10s 超时，进程 PID 变化）| 无前台服务，Dart 事件循环随进程冻结 | `McpService` 前台保活（锁屏 20s 实测 ping 恢复正常） |

## 6. 已知问题与后续项

### 6.1 已知限制（如实记录）

1. **prefs 落在 `code_cache/`**（`Directory.systemTemp` 的 Android 实际指向）——系统清理该目录时
   onboarding/凭据/MCP 开关会丢。**应迁 `files/`**（已列为下批首位修复）。
2. **UI 自动化受 MIUI 输入注入限流**：shell 身份的 `input tap` 时灵时不灵；真实手指操作不受影响。
3. **凭据 UI 保存→密文落盘的真机点验**未走通（同上注入限制）；加密链路（Keystore AES/GCM）为
   平台 API，代码层已 review + analyze 绿。建议人工：设置页编辑凭据 → 保存 →
   `su -mm -c "cat /data/user/0/dev.gitdeck/code_cache/gitdeck_prefs.json"` 应只见 `credEnc` 无明文。
4. 桌面平台（无 MethodChannel 通道）：凭据回退明文存储（代码注释已文档化），MCP 横幅自动隐藏。
5. MCP 仅监听 loopback：电脑侧 AI 需 `adb reverse`（同机 AI 如 Kelivo 直连）。
6. 容器侧（PRoot）curl 测 MCP 会被容器→设备网络中间层干扰（大响应被吞、注入安全头）——
   **测试通道一律用设备侧 curl**（np_execute_shell）。

### 6.2 后续批次

- **prefs 迁移 files/** + 旧位置迁移逻辑（下批首位）
- 工作台细化（第二批）/ 分支历史打磨（第三批）/ 商业化（第四批，按需求排除中）
- MCP：调用日志页、remoteAdd/SetUrl 工具、SSE 传输支持
- 前台服务通知点击跳转 App
