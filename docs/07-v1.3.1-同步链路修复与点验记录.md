## 点验中挖出并修复的引擎级 bug（3 处，同一轮全修）

### 🔴 P1：本地路径 push/fetch 传输层失败（本设备特有）

**现象**：推送到本地裸仓库（`/storage/emulated/0/...`）全部失败，报"推送被拒绝"——但实际是传输层错误被误标。

**定位过程**（关键工具链）：
- 容器（PRoot）里用同一份 git2 crate 写最小回归测试（`rust/tests/push_local.rs`）：
  - push 到 rootfs（/tmp）路径 → ✅ 正常
  - push 到 FUSE 挂载路径 → ❌ `error reading from the zlib stream`（pack I/O 被破坏）
  - `Repository::init_bare` 在 FUSE 上新目录 → ❌ `failed to rename lockfile ... ENOENT`
- 结论：这台设备的 FUSE/l2s 层破坏 libgit2 **传输路径**的 pack 写入（tmp+rename 模式），
  而 **odb 写入路径完全正常**（app 的提交、remoteAdd 都写过没问题）。
- 参考应用 pack 目录的 `.l2s.tmp_pack_*` 残留文件是同一破坏模式的既有证据。

**修复**：`push_local_inprocess` / `fetch_local_inprocess`——本地路径远程
（`/path` 或 `file://`）绕过传输层：revwalk 逐对象 odb 复制（幂等，同 sha 跳过）+ 直接更新引用；
非本地远程（https/ssh）仍走原传输路径。fetch 侧顺带修正 `shorthand()` 与
完整引用名混淆导致跳过所有分支的 bug（用 `name()` 判 `refs/heads/` 前缀）。

### 🟠 set_upstream 顺序 bug（3 个实例同根）

libgit2 的 `git_branch_set_upstream` 要求远程跟踪引用已存在；绑定远程后尚未 fetch 时必失败：
- push 侧：`.ok()` 静默吞掉 → 首推永远建不了跟踪
- pull 侧：报错阻断拉取

**修复**：① push 成功后先补 `refs/remotes/<remote>/<branch>` 跟踪引用（对齐 git CLI 行为，
libgit2 push 不自动做，这也是 ahead/behind 永远算不出来的原因）；
② `ensurePullTarget` 先 fetch 再设跟踪；③ `branch_set_upstream` 失败时退回
config 级设置（`branch.<b>.remote` + `branch.<b>.merge`）。

### 🟠 friendlyError 误标

`has(['push 失败', 'rejected', 'non-fast-forward'])` 把一切 push 失败（含传输层）都报成
"推送被拒绝：远程有你本地没有的提交"。**修复**：真拒绝单独识别（加 `cannot push` 关键字），
其余 push 失败保留原始错误文案。

## 通道层记录（排障耗时主力，记入技能素材）
